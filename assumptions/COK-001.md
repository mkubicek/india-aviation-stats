# Observation

In 2015-2016 DGCA used both `KOCHI` (large, ~50M total) and `COCHIN` (a small
~157k residual) on different route rows in the **same months** - both Cochin
International Airport (IATA COK). This is the dataset's only case of two distinct
source labels feeding one canonical airport concurrently.

Raw provenance:
- 2015-09: `KOCHI` ≈ 213,006 and `COCHIN` ≈ 39,810 (same airport, different routes)

# Interpretation

The two spellings are disjoint route subsets of one physical airport, so summing
them is correct - not a double-count. But because it is a *concurrent* same-airport
merge, the overlap gate must not accept it on a heuristic; it is declared
explicitly so any *future* undeclared concurrent merge reds CI.

# Decision

`COCHIN` and `KOCHI` → **COK**, declared in `mappings.yaml: concurrent_labels`.

# Evidence

- Cochin International Airport = COK / VOCI  - 
  https://en.wikipedia.org/wiki/Cochin_International_Airport

# Falsification

`concurrent-merge-declared` (airport=COK, labels=[COCHIN, KOCHI]): TRIGGERED if the
declaration is removed while the labels still co-occur; ORPHANED (advisory) if the
labels stop co-occurring in the data entirely.
